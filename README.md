Тестовый проект, мини-СУБД по учёту технических средств ТКДРМ.
Разрабатывается в свободное от основной работы время.
В открытом доступе залитой БД нет. Есть только её структура, описание моделей и рисунок схемы (ниже). На данный момент разработка идет с использованием около 9000 валидированных записей таблицы Device, при планируемом в проде их количестве до 20000.

Технологии: Python, Django, DRF, SQLite (перспектива - PostgreSQL).

Done:
- структура БД. На настоящее время 28 таблиц, не считая служебных Django.
- management-команда:
  - создание структуры таблиц БД (хардкод).
  - парсер легаси данных из Excel, первая партия (import3).
  - парсер легаси данных из Excel, вторая партия (import4).
- пять view-функций для шаблонов:
  - общий перечень объектов.
  - детализация одного объекта.
  - редактирование одного объекта.
  - создание нового объекта.
  - удаление одного объекта.
- те же view-функции для REST API.
- Для шаблонов пагинация (кастомная, самописная).
- Для шаблонов предзагрузка кверисетов при просмотре и редактировании объекта БД, сокращение времени загрузки одного объекта с 30 секунд до 30 мс.

Структура БД в виде схемы приведена в файле Untitled.pdf. Будет корректироваться по мере разработки.

- git clone репозиторий.
- Создать venv. Установить в него зависимости.
- cd tkdrm1
- Сделать одно из:
  - 1.
    - python manage.py makemigrations
    - python manage.py migrate
    - Обеспечить в общей папке с manage.py наличие двух легаси-Excel-файлов для импорта данных из них
    - python manage.py import3
    - ждать 15...60 минут
    - python manage.py import4
    - ждать 6..20 минут
  - 2.
    - получить от разработчика файл БД db.sqlite3 и положить его рядом с manage.py
- python manage.py runserver
